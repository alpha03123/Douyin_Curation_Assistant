# Douyin Browser Lab

This lab is intentionally isolated from the main action pipeline.

It starts a dedicated persistent browser profile, keeps the browser window open,
and records the network traffic generated by your manual actions in that exact
window.

## What it captures

- requests
- responses
- failed requests
- console logs
- page errors
- dialogs
- page navigation events
- session health changes
- manual action markers

Logs are written as `ndjson` so we can inspect and diff them later.

## Important rule

Use the browser window started by `watchBrowser.js`.

If you open a separate Chrome/Edge process yourself, its traffic will not be
reliably visible to this watcher.

## Files

- profile directory:
  `Douyin_Curation_Assistant/.runtime/lab-browser-profile`
- capture root:
  `Douyin_Curation_Assistant/.runtime/lab-captures`
- per-run live log:
  `.../live.ndjson`
- per-run summary:
  `.../summary.json`

## Start the watcher

From `Douyin_Curation_Assistant`:

```powershell
npm run lab:watch-browser
```

or from `Douyin_Curation_Assistant/server`:

```powershell
npm run lab:watch-browser
```

Optional flags:

```powershell
npm run lab:watch-browser:all
node server/labs/douyin_browser_lab/watchBrowser.js --filter xhr
node server/labs/douyin_browser_lab/watchBrowser.js --filter action
node server/labs/douyin_browser_lab/watchBrowser.js --target-url "https://www.douyin.com/video/7604471631310035697"
```

Filter modes:

- `action`: only action-related traffic such as like / collect / comment / login / verify
- `xhr`: `xhr`, `fetch`, `beacon`, and document requests
- `all`: every request seen by the watched browser context

## Manual markers

Inside the watcher-started browser window:

- `Ctrl+Shift+1` => mark `like`
- `Ctrl+Shift+2` => mark `collect`
- `Ctrl+Shift+3` => mark `comment`
- `Ctrl+Shift+4` => mark `note`

These markers are written into the same log stream, which makes it easier to
match your manual action to the exact request that followed.

## Recommended first test

1. Start the watcher.
2. Log in manually in the watcher-started browser if needed.
3. Open one fixed Douyin work page.
4. Press `Ctrl+Shift+1`, then manually click like once.
5. Press `Ctrl+Shift+2`, then manually click collect once.
6. Press `Ctrl+Shift+3`, then manually publish one short comment.
7. Close the browser window.
8. Share the generated `live.ndjson` or the session folder for analysis.

## Extract the latest action summary

From `Douyin_Curation_Assistant`:

```powershell
npm run lab:extract-actions
```

This reads the latest session by default and writes:

- `.../action-summary.json`

You can also target a specific session:

```powershell
node server/labs/douyin_browser_lab/extractActionSummary.js --session "watch-2026-04-02T04-54-31-561Z-a1a9e031"
```

## Run one browser action automatically

The runner uses the same lab profile and confirms success from the real network
response generated by the page.

From `Douyin_Curation_Assistant`:

```powershell
npm run lab:run-action -- --action like
npm run lab:run-action -- --action collect
npm run lab:run-action -- --action comment --comment-text "测试一下"
npm run lab:run-action -- --action bundle --comment-text "测试一下"
```

Optional flags:

```powershell
npm run lab:run-action -- --target-url "https://www.douyin.com/video/7604471631310035697"
npm run lab:run-action -- --action bundle --comment-text "测试一下" --keep-browser-open
```

Important:

- do not run the watcher and the runner at the same time on the same profile
- close the watcher browser first, then run the runner
- the runner is still part of the lab and does not touch the main action pipeline

## Session health

The watcher periodically checks:

- whether key session cookies still exist
- whether the page shows login prompts
- whether the page hits captcha / verification signals

This is only a health monitor for now. It does not try to keep the session
alive automatically yet.
